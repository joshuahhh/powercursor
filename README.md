# PowerCursor for the web

> **Everything in this repository was generated by an LLM**: the
> engine, the demo ports, the reverse-engineered specs in `reference/specs/`, and this README.

A TypeScript port of [PowerCursor](https://www.powercursor.com/) (Koert van Mensvoort,
Koen Hendrix, Pascal de Man; TU/e, 2006–2009), the Flash toolkit for **optically simulated
haptic feedback**: the system nudges the cursor (into holes, off hills, along gutters,
through sand), and the mismatch between what your hand does and what your eyes see feels
like touch. See chapter 5 of van Mensvoort's thesis *What You See Is What You Feel* (2009).

This repo reproduces the demos from the powercursor.com homepage and examples page, with
the original SWF running next to each port (via [Ruffle](https://ruffle.rs)) for comparison.

```sh
npm install
npm run dev
```

## How the cursor works

Browsers can't move the real cursor, and neither could Flash. Two input modes:

- **Pointer lock** (default): click the stage; the page receives raw mouse deltas and
  draws the only cursor. Nothing can drift. `Esc` releases.
- **Hidden system cursor**: what the original did. The real cursor is hidden over the stage
  and a mock cursor follows its movement plus the forces. The two drift apart and re-sync
  when the mouse leaves and re-enters the stage.

## Layout

- `src/pc/`: the engine, a faithful port of the AS2 toolkit:
  - `engine.ts`: `PC_Engine` (force combination, inertia/grip, walls, dimmers, speed limit, ball collisions, input)
  - `objects.ts`: ready-made objects (Hill, Hole, Twister, Target, Gutter, Pushgutter, Ramp, Wedge, Sand, Slick, Dimmer, Wall, Button)
  - `behaviours.ts`: behaviours attachable to any node (WallMaker, SlickMaker, SandMaker, HillMaker, RampMaker, ForceDimmer, ButtonMaker, EventDispatcher, DraggerMaker, Synchronizer)
  - `cursor.ts`: ArrowCursor (Arrow/Finger/Hand/GrabHand/… icons), PowerBall, BallCursor
  - `node.ts`, `timeline.ts`, `art.ts`, `hit.ts`: a small Flash-like display list (DOM-backed), timelines, SVG art with registration points, shape-flag hit testing
  - `debug.ts`: PowerGrid-style force field overlay, Watcher
- `src/demos/`: one file per demo.
- `public/lib/`: the toolkit's library art and sounds; `public/demos/`: per-demo assets
  (all extracted from the original SWFs with [JPEXS FFDec](https://github.com/jindrapetrik/jpexs-decompiler)).
- `reference/`: the original AS2 source and SWFs, per-demo specs (`specs/`), and
  `PORTING.md`, which explains how Flash concepts map onto the engine.

## Frame-rate independence

The AS2 engine ran once per Flash frame (25–30 fps) and added each force to the cursor's
speed once per frame. The port runs at display rate and scales per-frame impulses by
`dt / originalFrameTime`. Decay and integration keep AS2's `frameTime / 50` time factor.
The per-frame quantities objects read back (last displacement) are normalised to the
original frame. Every object formula is therefore unchanged from the AS2 source, and the
feel matches the original at 60 or 120 Hz.

## Using the engine

```ts
import { Engine, Stage, Hole, Gutter, ArrowCursor, WallMaker, art } from "./pc";

const stage = new Stage(600, 400, "#333");
document.body.append(stage.el);
const engine = new Engine(stage, { fps: 30 });

stage.addChild(new Hole({ strength: 3 })).set({ x: 100, y: 100, scale: 1.5 });
stage.addChild(new Gutter({ strength: 4 })).set({ x: 300, y: 200, rotation: 30 });
const walls = stage.addChild(await art("my-maze.svg", { hit: true }));
walls.addBehaviour(new WallMaker());
stage.addChild(await ArrowCursor.create());

engine.start();
```
